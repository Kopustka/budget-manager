# Budget Manager — Telegram Mini App (TMA)

> Product Requirements Document / источник правды по проекту.

## Роль исполнителя
Senior Full-Stack разработчик + UX/UI инженер. Задача — финансовый Telegram Mini App.

## Технологический стек
- **Frontend:** React (Vite) + Tailwind CSS + Zustand + dnd-kit
- **Backend:** Node.js (TypeScript) + PostgreSQL + Redis
- **Архитектура:** Feature-Driven Development (FDD) + Clean Architecture

---

## 1. Визуальный стиль и UI/UX (Гласморфизм)
- **Тема:** глубокая тёмная (космический чёрный/тёмно-серый, `#0D0E12`).
- **Стиль карточек:** гласморфизм — `bg-slate-900/40`, `backdrop-blur-xl`, `border-white/10`.
- **Акценты:** iOS-синий `#007AFF` для интерактивных элементов.
- **Алерты:** неоновый красный `#FF3B30` для индикации овердрафта.
- **Иконки:** минималистичные (Lucide React), адаптированные под iOS-стиль.
- **Telegram-специфика:**
  - программно отключать pull-to-refresh;
  - раскрываться на весь экран (`Telegram.WebApp.expand()`);
  - Haptic Feedback для всех жестов (Drag-and-Drop, свайпы);
  - для оптимизации рендера гласморфизма на мобилках — `will-change: transform`.

## 2. Навигация и Core-механики
- **Карусель времени:** полноценного календаря нет. Вверху экрана — горизонтальная скролл-карусель дат (ровно 30 дней назад от сегодня). Кнопка «+» интегрирована в карусель для добавления трат задним числом.
- **Пагинация категорий:** при большом числе карточек они разбиваются на страницы. Переход — горизонтальным свайпом (Framer Motion / Swiper).
- **Drag-and-Drop Матрица (`@dnd-kit/core`):**
  - `Доход -> Кошелёк` = Зачисление.
  - `Кошелёк -> Расход` = Списание. Открывается Bottom Sheet для ввода суммы и комментария.
  - `Доход -> Расход` = ЗАПРЕЩЕНО (карточка пружинит обратно, Haptic error).

## 3. История и редактирование транзакций
- История — лентой под основными блоками.
- Тап по старой транзакции открывает Bottom Sheet (аналогичный модалке создания расхода).
- **Возможности:** изменить сумму, добавить/изменить подкатегорию, изменить текстовый комментарий, перепривязать к другой категории, удалить транзакцию.

## 4. Аналитика и Дашборды
- **Бублик (Donut Chart):** распределение бюджета по категориям. Тап по сегменту — подсветка.
- **График скорости (Velocity Chart):** линейный тренд трат в сравнении с идеальной кривой (равномерным расходом). Recharts / Chart.js с неоновым glow-эффектом.

## 5. Уведомления и роль бота
- **UI-Алерты (real-time):** при перетаскивании денег с превышением лимита карточка мгновенно краснеет.
- **Telegram-бот:** фоновые воркеры в Node.js, брокер — Redis.
  - предупреждения о слишком быстрых тратах в течение дня;
  - уведомления при достижении лимита по категории;
  - вечерние напоминания («запиши траты») с кнопкой-ссылкой `web_app`, ведущей прямо в Mini App.

## 6. Бэкенд и базы данных (строгая архитектура)

### PostgreSQL (Source of Truth)
Таблицы:
- `users` — связь по Telegram ID
- `wallets`
- `categories`
- `category_limits`
- `transactions` — с индексами по времени и юзеру

### Redis (кэш и очереди)
- `ZSET: finapp:user:{id}:tx_cache:30d` — скользящее окно истории для карусели.
- `HASH: finapp:user:{id}:wallets` — текущие балансы.
- `HASH: finapp:user:{id}:spent:{YYYY-MM}` и `limits` — накопленные траты и лимиты для проверки овердрафта за <2 мс.
- `LIST / ZSET: finapp:queue:bot_alerts` — очереди для отложенных и моментальных пушей в Telegram-бота.

### Транзакционность
Все Drag-and-Drop операции обрабатываются на бэкенде **атомарно** (PG Transaction + Redis Pipeline).
